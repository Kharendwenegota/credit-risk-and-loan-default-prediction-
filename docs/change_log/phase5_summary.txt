PHASE 5: MODELING — SUMMARY
Credit Risk & Loan Default Prediction Project

Objective:
Train and compare multiple classification models to predict loan
default (TARGET), select a final model based on business-relevant
metrics (not accuracy alone, given severe class imbalance), and save
the selected model for use in later interpretability (Phase 6) and
deployment (Phase 7) work.

Input:
    data/processed/application_train_features.csv (307,507 rows x 347 columns)
Output:
    outputs/models/lightgbm_final_model.pkl


ACTIONS TAKEN
-------------
1. Loaded feature-engineered dataset; separated features (X) and
   target (y = TARGET), dropping SK_ID_CURR (identifier, not
   predictive)

2. Performed an 80/20 stratified train/test split (stratify=y) to
   preserve the ~92%/8% class balance in both sets

3. Filled missing values using TRAIN-set medians only (applied to
   both train and test sets) to avoid data leakage from test-set
   statistics — required for Logistic Regression, which cannot
   handle NaN natively; tree-based models (Random Forest, XGBoost,
   LightGBM) can handle NaN natively but were run on the same filled
   data for a fair, consistent comparison across all four models

4. Trained and evaluated four models:
   a) Logistic Regression (baseline)
      - class_weight='balanced' to address class imbalance
      - Features scaled via StandardScaler (required for linear
        models; not needed for tree-based models)
   b) Random Forest
      - class_weight='balanced', max_depth=10, n_estimators=200
   c) XGBoost
      - scale_pos_weight set to the train-set negative:positive class
        ratio (~11-12x) to address class imbalance
      - max_depth=6, n_estimators=300, learning_rate=0.05
   d) LightGBM
      - class_weight='balanced'
      - max_depth=6, n_estimators=300, learning_rate=0.05
      - Required a column-name sanitization step before fitting (see
        Notes below)

5. Evaluated all models on ROC-AUC, Precision, Recall, and F1-score
   for the default (TARGET=1) class specifically, rather than
   leading with overall accuracy — consistent with the class
   imbalance finding from Phase 1


RESULTS
-------
Model                   ROC-AUC   Precision(1)  Recall(1)  F1(1)   Accuracy
Logistic Regression     0.764     0.17          0.69       0.27    0.70
Random Forest           0.751     0.17          0.64       0.27    0.72
XGBoost                 0.778     0.19          0.67       0.29    0.74
LightGBM                0.778     0.18          0.69       0.29    0.73

(Precision/Recall/F1 reported for the minority/default class, i.e.
TARGET=1, since this is the class of actual business interest.)


FINAL MODEL SELECTION: LightGBM
----------------------------------
XGBoost and LightGBM are effectively tied on ROC-AUC (0.7782 vs
0.7783 — a difference of 0.0001, within noise) and both clearly
outperform Logistic Regression and Random Forest.

LightGBM was selected as the final model because:
    - It matches XGBoost's top ROC-AUC
    - It achieves the same recall as the Logistic Regression baseline
      (0.69) — the highest recall among the tree-based models
    - In credit risk, the cost of a missed default (false negative)
      is typically higher than the cost of a false alarm on a good
      applicant (false positive), making recall on the default class
      a business-relevant metric worth prioritizing at effectively
      equal ROC-AUC
    - XGBoost remains a very close, defensible alternative choice;
      the two are near-equivalent and either could reasonably be
      presented as "final" with the reasoning above

Random Forest underperformed both the linear baseline and the
gradient boosting models. This is a known pattern on datasets with
many sparse, correlated one-hot-encoded columns (this dataset has
several categorical fields with 20-70+ dummy columns) — Random
Forest's random feature selection at each split can get diluted
across many sparse dummy columns, whereas gradient boosting methods
and regularized linear models tend to handle this feature structure
more effectively. max_depth was also kept conservative (10) for
training speed, which likely contributed.

0.778 ROC-AUC is a strong single-model result for this dataset without
heavy tuning or ensembling — top Kaggle leaderboard solutions on this
exact dataset typically reach ~0.79-0.80 with significant additional
tuning, stacking, and ensembling.


NOTES / ISSUES ENCOUNTERED
-----------------------------
1. LightGBM column name error (LightGBMError on .fit()):
   LightGBM's underlying library rejects special characters (colons,
   commas) in feature names, which several one-hot encoded columns
   contained (e.g. "ORGANIZATION_TYPE_Industry: type 1",
   "NAME_TYPE_SUITE_Spouse, partner"). XGBoost and scikit-learn
   tolerate these characters; LightGBM does not.
   Fixed by sanitizing all column names (replacing any character
   that isn't a letter, number, or underscore with "_") before
   fitting LightGBM specifically, with a duplicate-column check
   afterward to confirm the sanitization didn't collapse two
   distinct column names into one.
   Lesson: when moving the same feature set between different ML
   libraries, don't assume column-naming conventions that work in
   one library will work in all of them.

2. A ModuleNotFoundError for pandas occurred mid-phase, traced to the
   notebook running on the wrong Python kernel (not the project's
   venv). Fixed by explicitly selecting the venv interpreter as the
   notebook kernel via VS Code's kernel picker.

3. application_train_features.csv was found missing at the start of
   this phase (likely never fully saved due to an earlier kernel
   session issue in Phase 3). Resolved by re-running
   03_feature_engineering.ipynb's merge and save cells to regenerate
   the file before proceeding with modeling.
